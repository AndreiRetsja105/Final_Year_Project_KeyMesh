# KeyMesh

Distributed key management for protecting medical records (National College of Ireland, final year project, 2026/27).

**Idea:** 
records are encrypted using AES256GCM, with a unique data key for each record (envelope encryption). The master key is never stored in its entirety; instead, it is split among eight independent key services using Shamir’s Secret Sharing algorithm (requiring 5 out of 8 shares).
Each key service releases its share only for short term, one time use, in the form of a signed decryption ticket bound to a specific user, record, and security epoch. The objective is to

**measure** 
how many independent components an attacker must compromise before recovering plaintext.

> Academic prototype. Development values only. **Synthetic data only, never real patient data.**

## Architecture

```
Internet >>>> api_gateway (only published port, :8443)
|  internal network
        +-- auth_service      (tickets, later:login, MFA)
        +-- data_service      (records, later:storage)
        +-- crypto_service    (only service on the "keys" network)
|  keys network
        +-- key service 1 key service 8 (one share each)
            postgres (db network only)
```

Containers run as a non root user with a read only file system, all Linux capabilities dropped and `no new privileges`

## Quick start (Windows, PowerShell)

Requires Python 3 and Docker Desktop (engine running)

|-------powershell commands---------|
||
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r services/requirements.txt pytest
pip install -e ./libs/keymesh_common

python -m pytest test_for_keymesh        # unit and smoke tests

copy .env.example .env                   # development values
python scripts/init_keys.py              # creates secrets/shares/share_1..8.txt 

(git-ignored)
docker compose up --build
```

Check: http://localhost:8443/health returns `{"service":"api_gateway", ... "status":"ok"}`.

each key service reports share_loaded: true on its internal /health:

```powershell
1..8 | ForEach-Object { docker compose exec key-service-$_ python -c "import urllib.request; print(urllib.request.urlopen('http://localhost:8000/health').read())" }
```

Stop with `docker compose down`.

## Security notes

- `.env` and `secrets/` are git-ignored and must never be committed.
- a known limitation is that the key is briefly reconstructed in memory during decryption. Plans are in place to mitigate this (e.g., restricted access via tokens, data keys for individual records, short key lifespans, and enhanced container security); threshold cryptography, HSMs, and TEEs are objectives for the future
